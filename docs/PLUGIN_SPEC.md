# LovelyCarve 插件规范（plugins.zig）

协议机制、宿主行为与 LPP 帧格式见[《LovelyCarve 插件协议（LPP）v2》](PLUGIN_PROTOCOL.md)。
本规范约束**本仓库**写插件的方式：目录与分类、记录的来源、版本、构建与质量要求。
新建或修改插件前先读完本文；协议文档管"宿主允许什么"，本文管"仓库要求什么"。

## 一、目录与分类

按**插件属性**放在 `plugins/` 的分类目录里，分类两级：`<分析域>/<平台>`（不绑定平台的插件省略平台级）。

```text
plugins/
├── evidence/                  # 以整个检材为对象的通用分析器，不绑定操作系统
│   └── apkanalyzer/           #   APK 分析（检材中的所有 APK）
├── system/<平台>/             # 系统级信息，绑定识别出的操作系统
│   └── windows/winsysteminfo/ #   Windows 系统信息（注册表）
└── appinfo/<平台>/            # 绑定平台的应用级信息（应用配置、口令、痕迹）
    └── windows/navicat/ …     #   Navicat 连接分析、MobaXterm 凭据分析
```

- 插件**目录名 = 插件 ID 的最后一段**（`com.wxjzc.winsysteminfo` ↔ `winsysteminfo`），小写字母与数字。
- 新分类先在本规范登记再建目录；分类按"分析对象"划分，不按记录类型或技术手段划分。
- 插件源码不得放在仓库根目录；根目录只放构建系统（`build.zig`、`scripts/`）、共享库（`libs/`、`zig-sdk/`）、模板（`zigtemplate/`）与文档（`docs/`）。

## 二、记录的来源：不自建"数据来源"字段

宿主为每条记录保留**系统来源**（`sources`，最多 16 条，见协议文档"分析运行"）：SDK 的
`.from(&file)` 从输入或视图打开的文件自动填写卷键、卷内路径与节点 ID，界面据此**定位源文件**直接跳转。

因此：

1. 记录默认**不携带**"数据来源 / 来源文件 / 所在文件"一类的列——这是宿主职责，重复了。
2. 产出每条记录时必须用 `.from(&file)` 绑定它**真正来自的文件**；同一运行覆盖多个输入时，各记录绑定各自的输入，而不是统一绑第一个。
3. 记录在来源文件内的位置用 `.note("第 12 行")` 或 `.at(offset, length)` 表达，不另开列。
4. **例外（需特意说明）**：字段参与**记录身份**时可以保留——同一运行覆盖多个来源文件、仅靠业务字段无法区分记录（如多个用户的 `NTUSER.DAT` 里各有一条同名连接）。保留的字段命名要体现身份含义，并在插件 README 说明保留原因。

## 三、版本

三段语义化版本 `<主>.<次>.<补>`，插件初始版本 **1.0.0**：

| 变更 | 版本动作 | 示例 |
| --- | --- | --- |
| bug 修复、内部实现调整；不改记录结构、选项语义与分析器行为 | 补丁位 +1 | 1.0.0 → 1.0.1 |
| 功能更新：新增分析器、记录类型、字段、选项；新增识别能力 | 次版本 +1，补丁位归零 | 1.0.3 → 1.1.0 |
| 重大/不兼容更新：已发布记录结构或选项语义变更、插件 ID / 记录命名空间变更、最低 SDK 或协议版本提升 | 主版本 +1，其余归零 | 1.1.0 → 2.0.0 |

- `plugin.toml` 的 `version` 与 `build.zig.zon` 的 `.version` 同步修改；安装包名
  `dist/<id>-<version>-<platform>.lcpkg` 随之变化。
- 发布（`zig build package`）前必须通过 `zig build test`。

## 四、其他规范

1. **身份与命名**：插件 ID 为 `com.wxjzc.<目录名>`，一经发布不可变更（改 ID 视为新插件）；分析器 ID、记录类型 `<目录名>.<类型>`、告警代码前缀（`<大写下划线名>_…`）与代码常量全部与之一致。显示名（`name`）是面向用户的中文名，可随功能演进调整。
2. **构建集成**：新插件必须在根 `build.zig` 的 `plugins` 表登记（目录、库名、所需辅助库）；仓库根的 `zig build test` / `zig build package` 是一次性验证与打包的唯一权威入口。共享脚本在根 `scripts/`（`pack.zig`、`drive.py`），插件内**不得复制**；插件自己的 `build.zig` 只为单独开发服务，打包行为必须与根构建一致（同样输出根 `dist/`）。
3. **清单一致性**：`plugin.toml` 的 `id` / `library` / `[[analyzer]]` 必须与代码中的常量一致（握手时宿主逐项校验，不一致直接拒载）；multi 选项留空的语义（全选还是全不选）必须在 README 写明。
4. **健壮性**：单个输入或单条数据失败用 `run.warn*` 上报并继续，不让整次运行失败；坏文件是告警不是错误。长循环轮询 `run.checkCancelled()`、上报 `run.progress`，结束时 `run.setSummary` 一句话概括运行结果。
5. **内存**：大文件逐个处理，读入缓冲用 libc 分配器、解析值用每文件 arena，读入上限写成具名常量并在 README 说明（模式见 winsysteminfo / apkanalyzer 的 `analyze.zig`）。
6. **测试与验证**：`zig build test` 必须覆盖解析核心的单元测试与 `lc.testing` 假宿主的端到端测试；真实样例用 `zig build probe`（或根 `scripts/drive.py` + 真宿主 `lc-plugin-host`）验证过才交付。
7. **文档**：每个插件一份 README——分析器表、记录表、选项表、构建与验证命令、与参考实现（如有）的差异；协议机制链接到 PLUGIN_PROTOCOL.md，不重复抄写。
8. **依赖**：只用 `zig-sdk` 与 `libs/` 下的共享库；新增共享库进 `libs/`（优先 git submodule 引入）并在根 `build.zig.zon` 登记，同时更新根 `build.zig` 的插件表开关。
9. **文案**：记录标签、运行摘要、告警消息以简体中文为默认；代码与注释使用英文。

## 五、日志

插件日志经宿主统一收集（见协议文档"日志"节）：`run.log(level, message)` 写入
LovelyCarve 日志与 `logs/plugins/<插件 ID>.log`，插件 stderr 同样入日志。日志是排查
"这条记录为什么有 / 为什么没有"的第一现场，以下四类信息必须落日志：

1. **实际解析的文件路径**：每处理一个输入，用 INFO 记一条它的实际路径（视图路径 /
   卷内路径 / 文件名）；一次运行覆盖多个输入时**逐条**记录，不得只记数量。
2. **关键节点过程**：解析的阶段性节点用 INFO 记录——进入/完成某个子项、成功派生
   引导密钥、定位到某个关键键或结构等，让日志能回放出解析实际走过的路径；节点与
   `run.progress` 的阶段划分对齐。
3. **解析结果**：运行结束时用 INFO 输出结果汇总——处理了几个输入、产出多少条记录、
   各子项的数量；文本与 `run.setSummary` 一致。
4. **异常与错误**：解析失败、数据异常、降级处置都要记录，级别用 WARN（可恢复，运行
   继续）或 ERROR（单个输入无法完成）。消息必须包含三要素——**对象**（文件路径、
   注册表键、偏移量）、**原因**（错误名 / 错误码、期望值与实际值）、**处置**（跳过、
   继续、降级）。禁止只记"失败"不记原因。

约定：

- 级别语义：DEBUG 只放开发调试细节；INFO 正常过程（路径、节点、结果）；WARN 可恢复
  的异常；ERROR 影响单个输入完成度的错误。整次运行失败直接返回错误，由宿主处理，
  不用 ERROR 表示。
- 日志面向取证人员：中文、可操作；密码明文等敏感内容只进记录（受结构保护），不进
  日志。
- 粒度：每个输入一条路径日志、每个阶段一至两条节点日志，不要逐条记录刷屏。

## 六、提交前 checklist

- [ ] 目录位置符合第一节，目录名与 ID 一致
- [ ] 记录没有多余的"来源"列；每条记录 `.from(&file)`；例外已在 README 说明
- [ ] 版本号按第三节调整，`plugin.toml` 与 `build.zig.zon` 一致
- [ ] 日志四类信息齐全（路径、节点、结果、异常），级别与粒度符合第五节
- [ ] 根 `build.zig` 的 `plugins` 表已登记/更新
- [ ] `zig build test`（根）全绿；`zig build package` 出包；真宿主端到端跑过
- [ ] README 的分析器/记录/选项表与实现一致
